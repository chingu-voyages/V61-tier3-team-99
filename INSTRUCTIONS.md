## Key Rules

- **Check `docs/team_decision_log.md` before assuming the tech stack.** The team is still voting on BE/FE language, framework, hosting, and repo structure. Don't generate boilerplate that locks in choices the team hasn't made.
- **Don't modify `docs/` files** unless explicitly asked — these are team-owned documents.
- **Branch from `dev`**, not `main`. PRs should target `dev`.
- **Keep PRs focused.** One concern per PR. Don't bundle unrelated changes.
